# AI Reading Teacher

Minimal native Android companion app for reading in any ordinary PDF reader, browser, Zotero,
or similar app. Milestones 0–5 plus live subtitles and answer preferences are implemented in
version 1.0.0.

## What it does

1. The user saves an OpenAI API key in Settings and presses **Start Teacher**.
2. Android asks for microphone and screen-sharing permission.
3. A foreground service captures the approved reading screen and starts a WebRTC voice session.
4. Screen changes are detected locally every 100 ms at 96 × 54 pixels.
5. After a changed screen is stable for about 250 ms, one full frame is saved, resized to at most
   1600 px, adaptively compressed below the WebRTC message limit, and sent as the latest tutor
   context. If a newer page arrives during encoding, it supersedes the older pending frame.
6. A screenshot never creates a response. The tutor remains silent until server VAD detects that
   the user has spoken.
7. WebRTC carries microphone and model audio with its integrated echo cancellation, jitter buffer,
   and speaker playback. Speaking over an answer interrupts it; OpenAI automatically truncates the
   unplayed WebRTC audio from conversation history.
8. **Stop Teacher** releases projection, peer connection, microphone, and audio playback.
9. Assistant audio transcript events stream into the main screen. An optional draggable overlay
   shows up to five lines over the reading app; tap it to hide it until the next answer.

## Small architecture

```text
ui/
    MainScreen
    SettingsScreen
service/
    TeacherService
    TeacherRuntime
capture/
    ScreenCaptureManager
    ScreenChangeDetector
    FrameProcessor
audio/
    AudioRecorder / AudioPlayer (legacy WebSocket transport only)
tutor/
    TutorProvider
    TutorSession
    TutorConfig / ProviderCapabilities
provider/openai/
    OpenAIWebRtcProvider
    OpenAIRealtimeProvider (legacy fallback, not selected by the service)
    OpenAIRealtimeProtocol
settings/
    SettingsRepository
    SecureApiKeyStore
```

`TutorProvider` keeps Realtime transport details out of screen capture, audio, service, and UI code.
Only OpenAI is implemented; another provider can implement the same small interface later.

## Settings and credential security

- Provider, model, and HTTPS base URL use Android DataStore.
- Global answer preferences and the floating-subtitle switch also use Android DataStore. User
  preferences are appended after protected built-in reading and prompt-injection rules.
- The API key is encrypted with AES-GCM using a non-exportable key generated by Android Keystore.
- Only ciphertext and its random IV are stored in private app preferences.
- Backups are disabled and no credential is present in source code, Gradle files, or Git.

This no-backend MVP posts the WebRTC offer directly from the tablet to `/v1/realtime/calls` with a
standard API key. Encryption protects
the key at rest, but a rooted/compromised tablet can still access credentials while the app is
running. Use a restricted project key with a spending limit and revoke it if the tablet is lost.
OpenAI recommends WebRTC for mobile clients, but recommends keeping a standard key on a backend.
That backend and ephemeral-token flow are deliberately outside this MVP's requested scope.

The default model is `gpt-realtime-2.1`, and the default endpoint is
`https://api.openai.com/v1`. Both are editable because model availability can vary by account and
change over time.

## Build and checks

Use JDK 17 and Android SDK 36:

```powershell
.\gradlew.bat testDebugUnitTest
.\gradlew.bat lintDebug
.\gradlew.bat assembleDebug
```

The APK is generated at:

```text
app/build/outputs/apk/debug/app-debug.apk
```

Local unit tests cover screen stability, secure endpoint validation, WebRTC session configuration,
Realtime JSON events, interruption position, and the guarantee that an image update does not
contain `response.create`.
They do not contact OpenAI and cannot prove microphone quality, speaker echo cancellation, account
model access, network latency, or visual answer quality; those require the tablet test below.

## Test version 1.0.0 on a real tablet

1. Install over the previous version:

   ```powershell
   adb install -r app\build\outputs\apk\debug\app-debug.apk
   ```

2. Open the app, select **Settings**, enter an API key, keep the default model/base URL initially,
   and press **Save**.
3. Press **Start Teacher** and approve microphone, notification, and screen-sharing requests.
4. Share an ordinary browser or PDF reader. Leave a readable page still for about one second.
5. Return briefly to the app. `Screen` should be `Active`, `Voice` should be `Listening`, and
   `Last context sent` should contain a recent time.
6. Leave the page unchanged for several seconds. The context time must not continuously update.
7. Ask a question about the visible page. The tutor should answer by voice using that page.
   Its words should stream into **Live AI transcript**. If floating subtitles are enabled and the
   Android special-access permission is granted, the same words should appear over the reader.
   Drag the subtitle to move it or tap it to hide it until the next answer.
8. While it is answering, speak another question. Playback should stop quickly and the new question
   should be handled.
9. Change page and wait for it to settle. The context time should update once, and the tutor must
   remain silent until another spoken question.
10. Press **Stop Teacher** or the notification action. The notification must disappear and the UI
    must show screen inactive and voice disconnected.

Some DRM-protected or secure screens intentionally produce a black image. Test first with an
ordinary browser or non-protected PDF.


Expected events include:

```text

SCREEN_CHANGED
WAITING_FOR_STABILITY
STABLE_SCREEN_CAPTURED
VOICE_CONNECTED transport=webrtc
IMAGE_SENT_TO_TUTOR

```

The debug PNG remains available in the private app directory at
`files/debug_capture/latest_capture.png`.

## Current MVP boundaries

- No ebook reader, OCR, RAG, notes, accounts, backend, analytics, or cloud synchronization.
- No automatic Realtime reconnection yet; connection failures stop the Teacher with a visible error.
- Live OpenAI behavior is intentionally not part of local automated tests because no API key is
  stored in the repository or build environment.

Implementation follows the official OpenAI
[Realtime WebRTC guide](https://developers.openai.com/api/docs/guides/realtime-webrtc) and
[Realtime conversations guide](https://developers.openai.com/api/docs/guides/realtime-conversations).
